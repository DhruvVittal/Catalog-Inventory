02 · OBJECT-ORIENTED DESIGN

OOP concepts you can find in the code

A

Encapsulation

Product keeps its fields private and exposes getters and setters. Other code works with the product through that public interface.

Open the catalog
B

Abstraction

ProductRepository describes data operations. The service can ask it to find products without knowing the SQL or database connection details.

See the repository
C

Inheritance

ProductRepository extends JpaRepository<Product, Long>. It inherits standard save, delete, and lookup operations from Spring Data.

Browse products
D

Polymorphism

The service depends on the ProductRepository interface. Spring provides a generated implementation behind that interface at runtime.

Trace a page request
E

Composition

ProductService has a ProductRepository field. The service is built from a collaborator rather than inheriting repository behavior.

View inventory
F

Single responsibility

The controller handles HTTP details, the service coordinates app behavior, and the repository handles persistence. Each layer has a focused job.

Try the app
03 · PAGINATION

How the product pages work

The browser requests a slice instead of downloading the entire catalog. Page numbers in the API start at zero. With page size 10, page 2 starts at offset 2 × 10 = 20.

GET /api/products/page?page=2&size=10&sortBy=name&direction=asc

The repository returns a Spring Page<Product>. The API wraps it in a small response object, and the browser enables or disables Previous and Next from the returned page counts.

Why paginate on the server?For a large catalog, loading every row wastes memory and network time. The database returns only the requested page and calculates the total count.
